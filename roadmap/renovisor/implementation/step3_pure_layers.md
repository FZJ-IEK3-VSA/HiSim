## 3. `catalogue.py` — the catalogue loader and id derivation (Q1)

The only reader of `measures.yaml`. It produces typed specs and derives the ids the catalogue
does not yet carry.

```python
@dataclass(frozen=True)
class OptionSpec:
    option_id: str            # snake_case from the catalogue's option name: "type of system" -> "type_of_system"
    display_name: str         # the catalogue's option name verbatim
    value_type: OptionValueType   # Enum: ENUM, INTEGER, BOOLEAN
    access_level: AccessLevel     # Enum: EVERYONE, EXPERTS
    values: Tuple[str, ...]   # enum values in wire spelling (see below); integer value lists as strings too
    display_values: Tuple[str, ...]   # the catalogue's spellings, same order (for the map, V3)

@dataclass(frozen=True)
class MeasureSpec:
    measure_id: str           # UPPER_SNAKE from display_name: "external insulation" -> "EXTERNAL_INSULATION"
    display_name: str
    category: str
    subcategory: str
    options: Tuple[OptionSpec, ...]

class Catalogue:
    """All 33 measures; loaded from ContractFiles.measures() by Catalogue.load()."""
    def by_id(self, measure_id: str) -> MeasureSpec   # KeyError -> callers turn it into a validation error
    def measure_ids(self) -> Tuple[str, ...]
```

**Id derivation** (`IdDerivation` class with two classmethods): replace every run of characters
that is not `[A-Za-z0-9]` by `_`, strip leading/trailing `_`, upper-case for measure ids and enum
values, lower-case for option ids. When the catalogue carries an explicit `id:` on a measure,
option or value (the contract PR will add them), that id wins over derivation. A test asserts the
33 derived ids are unique and equal the list in `challenges.md` §9 Q1's convention.

(`SURFACE_HEATING`, `MECHANICALEXTRACT`, `EPS Foam`). C3 says the contract will carry HiSim

value to the HiSim member, per option:

## 4. `options.py` — reading a measure's options from a request (Q1, M7)

```python
class Options:
    """The option values one package entry supplies for one measure, validated against its MeasureSpec."""
    def __init__(self, spec: MeasureSpec, supplied: Mapping[str, object], report: MappingReport, path: str)
    def enum(self, option_id: str) -> str                  # HiSim value; ValidationError on unknown option/value
    def integer(self, option_id: str, default: Optional[Default] = None) -> int
    def boolean(self, option_id: str, default: Optional[Default] = None) -> bool
    def is_supplied(self, option_id: str) -> bool

@dataclass(frozen=True)
class Default:
    value: object
    source: str        # where the number comes from; appears in the report line
```

Rules: an option id not in the spec, a value not in an enum's list, a value of the wrong type, or
a key in the request the spec does not know is a `ValidationError` (§6) naming the JSON path
(`package.measures[3].options.thickness_in_mm`). An absent Experts option with a `Default` records
a `defaulted` report line with the source (M7). An absent option without a default is a
`ValidationError`. Booleans must be JSON booleans, never strings.

## 5. `effects.py` — the closed effect set and the accumulator

Frozen dataclasses, one per row of `measures_v2_requirements.md` §7.3, plus two this step adds:

| Effect | Fields |
|---|---|
| `AddThermalResistance` | `element: ThermalElement`, `material_asp_id: str`, `thickness_in_mm: int`, `measure_id` |
| `SetUValue` | `element`, `u_value_in_watt_per_m2_per_kelvin: float`, `measure_id` |
| `SetInventoryField` | `path: str`, `value: object` **or** `law: LawRequest`, `measure_id` |
| `SelectVariant` | `variant: str`, `option: str`, `measure_id` |
| `EnableGroup` | `group: str`, `measure_id` |
| `SelectBaseFile` | `generator: Optional[HeatGenerator]`, `solar_thermal: Optional[SolarThermalSupplies]`, `cars: Optional[int]`, `dhw_supply: Optional[DhwSupply]`, `measure_id` — each field `None` when the measure does not speak to it |
| `NoEffect` | `reason: ReasonCode`, `measure_id` |
| `Refusal` | `reason: ReasonCode`, `path: str`, `detail: str`, `measure_id` |

`LawRequest(law: SizingLaw, argument: float)` where `SizingLaw` is an Enum
`{PV_SHARE_OF_ROOF, BATTERY_FROM_DAYS_TO_COVER}`. A law value is **not** resolved in this step: it
needs simulation inputs (the LPG profile, the TABULA heating demand) that the parametriser of step
5 has. This step records the request; the report line says `approximated` and names the law.

`Effects` is the accumulator measures write into (`add_thermal_resistance(...)`, `set_u_value(...)`,
`set_inventory_field(...)`, `select_variant(...)`, `enable_group(...)`, `select_base_file(...)`,
`no_effect(...)`, `refuse(...)`), each appending one frozen effect. `Effects.resolve(inventory,
current_u_values) -> ResolvedEffects` runs after **all** measures (M2):

1. Group `AddThermalResistance` and `SetUValue` by element. Per element: baseline U is the last
   `SetUValue` if any, else `current_u_values[element]` (§9); `U_new = 1 / (1/U_baseline + Σ d/λ)`
   over every resistance; write one `envelope_details.<element>_u_value_in_watt_per_m2_per_kelvin`.
2. Collect `SetInventoryField` into `writes: Dict[path, value | LawRequest]`; two writes to one path
   with different values → `Refusal(CONFLICTING_WRITES)`.
3. Collect variant selections (two options for one variant → `Refusal(CONFLICTING_WRITES)`), groups,
   and merge `SelectBaseFile` fields (two different generators → `Refusal(CONFLICTING_WRITES)`).
4. Keep every `NoEffect` and `Refusal`.

An `assert_never` over the effect union in the resolver makes a new effect type a mypy error until
it is handled.

## 8. Materials: `materials_import.py`, `materials.py`, `data/insulation_materials.json` (Q5, Q6)

**Import script** `python -m hisim.renovisor.materials_import` reads
`ContractFiles.materials()` and writes `hisim/renovisor/data/insulation_materials.json`:

```json
{ "source": {"contract_commit": "<from PINNED.yaml>", "file": "materials.yaml", "sha256": "<from PINNED.yaml>"},
  "materials": [
    { "asp_id": "wood_fiber_rigid_board", "name": "Wood fiber - Rigid board",
      "thermal_conductivity_in_watt_per_meter_per_kelvin": 0.041,
      "lifespan_in_years": {"low": 50, "high": null, "raw": "≥ 50"},
      "investment_cost_in_euro_per_m3": {"IE": {"low": 260, "high": 660}, "ES": {...}, "NL": {...}},
      "co2_footprint_in_kg_per_m2": 11.421507, "co2_storage_in_kg_per_m2": -36.981043,
      "end_of_life": ["Re-Use", "Recycling", "Composting"],
      "comparison_baseline": false,
      "sources": "<the Sources text verbatim>",
      "summary": "<the summary text verbatim>" }, ... ] }
```

Parsing rules, each with a unit test: conductivity must be a number, else the row **fails the
import** with its `asp_id` and the offending value (no defaulting, no skipping). Ranges are parsed
by one `RangeParser` class: `"110 - 270"`, `"28-45"`, `"≥ 50"`, `"50"`, `"40-75"`; a value that
does not parse becomes `null` with the raw string kept in `"raw"`; cost `min`/`max` that are not
numbers (`'n'`, `'41-80'`, `'41-80€/m2'`) become `null` with `raw`. Heat capacity and density
are **not** imported (the XPS heat capacity is a conductivity, `eps_beads_cavity`'s is garbage;
they are not needed). Component-application vocabulary is not imported (C11). The script prints a
row-by-row summary and exits non-zero on any failed row.

**Reader** `materials.py`: `InsulationMaterials.load()` → `by_asp_id(asp_id) -> Material`
(frozen dataclass mirroring the JSON), `KeyError` for an unknown id. A test regenerates the table
from the vendored dump in a temporary directory and asserts it equals the committed file, so a
materials refresh without a re-import fails the build.

## 10. `inventory.py` — the typed, path-addressed inventory

```python
class Inventory:
    """A HomeInventoryInput as a dict with dotted-path access; validated against the vendored OpenAPI schema."""
    @classmethod
    def from_dict(cls, data: Mapping) -> "Inventory"    # deep copies
    def get(self, path: str, default=None)              # "building_config.envelope_details.roof_area_in_m2"
    def set(self, path: str, value) -> None             # creates intermediate dicts
    def has(self, path: str) -> bool
    def to_dict(self) -> Dict
    def validate(self) -> None                          # raises ValidationError(SCHEMA_VIOLATION, path, detail)
```

Validation uses `jsonschema` (installed, 4.26) with the `HomeInventoryInput` schema from
`ContractFiles.openapi()["components"]["schemas"]`, resolving `$ref`s within the document
(`jsonschema.validators.RefResolver` or the `referencing` registry rooted at the document).
OpenAPI's `nullable: true` is a 3.0 keyword unknown to JSON Schema; before validating, rewrite
every `{type: X, nullable: true}` into `{type: [X, "null"]}` in a copy of the schema (one small
`OpenApiSchemaAdapter` class). `examples` and `x-*` keys are ignored by validators.

`PendingContractPaths`: a class attribute listing the inventory paths this step writes or reads
that the vendored contract does **not** yet define, each with the decision id that adds it:

## 13. `application.py` — applying a package to an inventory

```python
@dataclass(frozen=True)
class PackageEntry:            # one element of PackageDefinition.measures after Q1
    measure_id: str
    options: Mapping[str, object]

class PackageApplication:
    """Applies one package to a copy of the inventory (R5) and returns everything the parametriser needs."""
    def __init__(self, catalogue: Catalogue, registry: MeasureRegistry, materials: InsulationMaterials,
                 current_u_values_factory: Callable[[Inventory], CurrentUValues])
    def apply(self, inventory: Inventory, package: Sequence[Mapping[str, object]]) -> ApplicationResult

@dataclass(frozen=True)
class ApplicationResult:
    inventory: Inventory                 # post-measure copy, in the inventory's own units (M5), law values pending
    base_file_key: BaseFileKey           # from the inventory's heating system, overridden by SelectBaseFile effects
    variant_selections: Dict[str, str]
    enabled_groups: Tuple[str, ...]
    pending_laws: Dict[str, LawRequest]  # inventory path -> law, for step 5
    report: MappingReport
```

Order of work in `apply`: (1) validate the package shape: a list of objects with exactly the keys
`measure_id` and `options`; any other key, in particular `stage`, is `ValidationError(
UNKNOWN_KEY_IN_MEASURE)` and `stage: 0` specifically `STAGE_ZERO_MEASURE` (Q4, fail hard); a
`measure_id` not in the catalogue → `UNKNOWN_MEASURE`; the same `measure_id` twice →
`DUPLICATE_MEASURE`. (2) Deep-copy the inventory. (3) Read the base-file key from the inventory
(`heating_system.system` → `HeatGenerator`, solar thermal block present → `True`, `vehicles.
electric_vehicles` length). (4) Run every registry function with its `Options`. (5)
`Effects.resolve(...)` with `InventoryThenTabula`. (6) Exclusivity and fit checks (§9). (7) If any
`Refusal` exists → raise `RefusalError` carrying **all** refusals (the caller writes them all into
`errors.json`). (8) Write the resolved U-values and inventory fields into the copy; record `report`
lines; `report.finalize(post_inventory)`. (9) Validate the post-measure inventory against the
schema, ignoring `PendingContractPaths` (AC4.1 with the pending list).
